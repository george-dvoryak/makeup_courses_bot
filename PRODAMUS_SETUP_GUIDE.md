# Руководство по настройке Prodamus

## 1. Конфигурация в .env файле

Добавьте следующие переменные в ваш `.env` файл:

```env
# Prodamus настройки
ENABLE_PRODAMUS=True
PRODAMUS_TEST_MODE=True  # True для тестирования, False для продакшна
PRODAMUS_PAYFORM_URL=testwork1.payform.ru  # Для теста, или ваш продакшн домен
PRODAMUS_SECRET_KEY=ваш_secret_key_из_личного_кабинета
PRODAMUS_SYSTEM_ID=ваш_system_id  # Опционально, если требуется
PRODAMUS_TEST_WEBHOOK_URL=https://webhook.site/ваш-id  # Опционально, для отладки
```

## 2. Получение Secret Key

1. Войдите в личный кабинет Prodamus: https://prodamus.ru/
2. Перейдите в **Настройки** → **Безопасность**
3. Найдите раздел **Secret Key** (или **Ключ для подписи**)
4. Скопируйте ключ и добавьте в `.env` как `PRODAMUS_SECRET_KEY`

## 3. Настройка Webhook URLs в Prodamus

В личном кабинете Prodamus нужно настроить следующие URL:

### 3.1. Result URL (обязательно) ⭐

**Это самый важный URL** - сюда Prodamus отправляет уведомления о статусе платежей.

1. Перейдите в **Настройки** → **Уведомления** (или **Webhooks**)
2. Найдите поле **Result URL** (или **URL для уведомлений**)
3. Укажите: `https://ваш-домен.pythonanywhere.com/prodamus/result`
4. Метод: **POST**
5. Сохраните настройки

**Важно:** Этот URL должен быть доступен из интернета и принимать POST запросы.

### 3.2. Success / Fail URL (необязательно)

Эти адреса отвечают только за редирект пользователя после оплаты и **не участвуют** в обработке платежей внутри бота. Вы можете:

- Оставить их пустыми
- Указать любую статическую страницу с информацией для клиента

> ⚠️ Все действия по выдаче доступа выполняются только через Result URL.

## 4. Проверка конфигурации

Запустите скрипт проверки:

```bash
python3 check_prodamus_config.py
```

Этот скрипт покажет:
- Текущие настройки Prodamus
- Правильные URL для настройки в личном кабинете
- Проблемы в конфигурации

## 5. Тестирование webhooks

### 5.1. Проверка доступности endpoints

```bash
python3 test_prodamus_webhook.py
```

Этот скрипт отправит тестовые запросы к вашим webhook endpoints.

### 5.2. Тестовая оплата

1. В личном кабинете Prodamus убедитесь, что включен **тестовый режим**
2. Создайте тестовый платеж через бота
3. Используйте тестовые карты из документации Prodamus:
   - Успешная оплата: `4111 1111 1111 1111`
   - Неуспешная оплата: `4000 0000 0000 0002`
4. Проверьте логи на сервере (Error log в PythonAnywhere)

## 6. Структура webhook запросов

### Result URL (POST)

Prodamus отправляет POST запрос с form-data:

```
order_num=PROD-20251112180945692-314112021-3
order_id=37934589
sum=100.00
currency=rub
customer_email=user@example.com
payment_status=success
payment_status_description=Успешная оплата
```

Подпись отправляется в заголовке `sign` или в параметре `signature`.

### Success URL (GET)

Пользователь перенаправляется с параметрами:

```
_payform_status=success
_payform_id=37934589
_payform_order_id=PROD-20251112180945692-314112021-3
_payform_sign=подпись
```

## 7. Проверка подписи

Код автоматически проверяет подпись всех webhook запросов:

1. Извлекает все параметры кроме `sign`/`signature`
2. Сортирует их по алфавиту
3. Объединяет в строку через `&`
4. Добавляет Secret Key
5. Вычисляет MD5 хеш
6. Сравнивает с полученной подписью

Если подпись не совпадает, запрос отклоняется с ошибкой 400.

## 8. Обработка платежей

### 8.1. Процесс оплаты

1. Пользователь выбирает курс и способ оплаты "Prodamus"
2. Бот запрашивает email (если не сохранен)
3. Генерируется уникальный order_id (формат: `PROD-YYYYMMDDHHMMSS-USER_ID-COURSE_ID`)
4. Создается ссылка на оплату с параметрами
5. Пользователь переходит на страницу оплаты Prodamus
6. После оплаты Prodamus отправляет уведомление на Result URL
7. Бот обрабатывает уведомление и выдает доступ к курсу

### 8.2. Хранение pending payments

До получения подтверждения от Prodamus платеж сохраняется в таблице `pending_payments`:

- `order_id` - уникальный ID заказа
- `user_id` - ID пользователя Telegram
- `course_id` - ID курса
- `amount` - сумма платежа
- `created_at` - время создания
- `payment_method` - метод оплаты ("prodamus")
- `customer_email` - email покупателя (если указан)

После подтверждения платеж удаляется из `pending_payments` и добавляется в `purchases`.

## 9. Отладка

### 9.1. Логирование

Все события логируются с префиксом `[Prodamus]`:
- `[Prodamus Result]` - обработка Result URL
- `[Prodamus Success]` - обработка Success URL
- `[Prodamus Fail]` - обработка Fail URL
- `[Prodamus TEST MODE]` - события в тестовом режиме

### 9.2. Тестовый webhook

Если установлен `PRODAMUS_TEST_WEBHOOK_URL`, все webhook данные также отправляются туда для отладки.

Рекомендуется использовать https://webhook.site для получения тестовых запросов.

### 9.3. Проверка логов

На PythonAnywhere проверьте:
- **Error log** - там будут логи обработки webhooks
- **Server log** - там будут логи запуска приложения

## 10. Переход в продакшн

1. Установите `PRODAMUS_TEST_MODE=False` в `.env`
2. Измените `PRODAMUS_PAYFORM_URL` на ваш продакшн домен
3. Убедитесь, что Secret Key правильный (для продакшна может быть другой)
4. Обновите webhook URLs в личном кабинете Prodamus на продакшн домен
5. Протестируйте реальный платеж

## 12. Частые проблемы

### Проблема: Webhook не приходит

**Решение:**
1. Проверьте, что Result URL доступен из интернета
2. Убедитесь, что URL правильно настроен в личном кабинете Prodamus
3. Проверьте, что веб-приложение запущено и работает
4. Проверьте логи на сервере

### Проблема: "Invalid signature"

**Решение:**
1. Убедитесь, что `PRODAMUS_SECRET_KEY` правильный
2. Проверьте, что Secret Key соответствует вашему аккаунту (тестовый/продакшн)
3. Проверьте логи - там будет показана полученная и вычисленная подпись

### Проблема: Платеж не обрабатывается

**Решение:**
1. Проверьте логи - там будет указана причина
2. Убедитесь, что order_id совпадает с тем, что в базе данных
3. Проверьте, что сумма платежа совпадает
4. Убедитесь, что курс существует
